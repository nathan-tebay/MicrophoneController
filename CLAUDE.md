## Project Overview

A 2-button USB HID microphone controller built on the **nullbits Bit-C PRO (ATmega32U4)**.
Each button supports tap-to-toggle and hold-for-push-to-talk. A mode switch selects between keyboard and gamepad HID output. LEDs reflect each mic's state.

## Hardware

### Wiring

| Signal | Pin | Notes |
|--------|-----|-------|
| Button 1 | D2 | To GND; internal pull-up enabled |
| Button 2 | D3 | To GND; internal pull-up enabled |
| LED 1 | D4 | ~220 Ω resistor to GND |
| LED 2 | D5 | ~220 Ω resistor to GND |
| Mode switch | D6 | To GND = keyboard mode; floating/HIGH = gamepad mode |

### Button behavior

| Action | Keyboard mode | Gamepad mode |
|--------|---------------|--------------|
| Tap | Toggle mic (sends key press + release; LED tracks toggle state) | Brief joystick button press |
| Hold (≥ 300 ms) | PTT — key held until released; LED on while held | Joystick button held; LED on while held |
| Mode switch change | All keys released; toggle states reset | All joystick buttons released |

## Key / Button Assignments

### Keyboard mode

| Button | Key | Rationale |
|--------|-----|-----------|
| 1 | `Scroll Lock` | Vestigial key, never bound by default in any major game engine or title; fully supported for PTT in Discord, TeamSpeak, Mumble |
| 2 | `F24` | Highest function key; only generated by specialty hardware so it cannot be accidentally triggered from a standard keyboard; recognized by all modern game engines and VoIP apps |

To remap, change `MIC_KEYS[2]` in [MicrophoneController.ino](MicrophoneController.ino).

### Gamepad mode

Joystick buttons **20 and 21** (1-indexed as reported to the OS/games).
The device declares 32 buttons in its HID descriptor; the two active buttons use 0-indexed slots 19 and 20.

**Why buttons 20–21:** The highest button count of any current standard or elite controller over USB HID is 14 (PS5 DualSense). Xbox Elite Series 2 back paddles remap to existing button slots rather than adding new HID indices. Buttons 20–21 are safely beyond all shipping hardware and will not shadow default gameplay bindings.

## Architecture

All logic lives in a single sketch file: [MicrophoneController.ino](MicrophoneController.ino).

### Key constants

| Constant | Default | Purpose |
|----------|---------|---------|
| `HOLD_MS` | `300` | Milliseconds held before a press is treated as a hold/PTT |
| `DEBOUNCE_MS` | `20` | Debounce window in milliseconds |
| `MIC_KEYS[2]` | `{ KEY_SCROLL_LOCK, KEY_F24 }` | Keyboard keys for each button |
| `JOY_BTN[2]` | `{ 19, 20 }` | 0-indexed joystick button slots |

### `Button` struct fields

| Field | Type | Purpose |
|-------|------|---------|
| `lastRaw` | `bool` | Last debounced pin reading |
| `pressed` | `bool` | Current debounced press state |
| `holdFired` | `bool` | True once hold threshold was crossed this press |
| `toggleState` | `bool` | Keyboard mode: whether mic is currently toggled on |
| `pressStart` | `ulong` | `millis()` at press start, used for hold detection |
| `lastDebounce` | `ulong` | `millis()` at last raw-state change, used for debounce |

### Key functions

- `handleButton(idx)` — debounce, press/hold/release detection, HID output, LED update for one button
- `readMode()` — reads `MODE_PIN` and returns `KEYBOARD_MODE` or `GAMEPAD_MODE`
- `releaseAll()` — releases all keyboard keys and joystick buttons; resets all button state; called on mode switch

## VS Code / IntelliSense

The `#include` errors for `Keyboard.h` and `Joystick.h` are IntelliSense path issues only — the code compiles correctly from the Arduino IDE.
To resolve squiggles: open the command palette and run **Arduino: Board Config**, select **Arduino Leonardo**, then run **Arduino: Rebuild IntelliSense Configuration**.
